# 日志与静态诊断

## 将报告绑定到输入

记录日志时间、游戏/Mod版本和候选hash。使用校验器时再记录工具版本、完整参数、descriptor、依赖根与实际加载顺序。来源不明的报告仍可分析，但不能将其缺陷直接归给当前候选。

按语法、字段/数据库、scope、缺失引用、版本/依赖分组。诊断级别用于排序，不证明对应运行故障已发生。区分工具执行失败、脚本发现问题与缺乏运行证据。

## 从现象到可验证修复

每个相关问题保留原文/位置、受影响调用链、根因假设、修复与判据。对照旧基线列新增、已解决和保留项；不要为小修复清空无关警告，也不要抹掉尚未解决的旧失败。

有已接入的Tiger或其它校验器时，先读真实版本与help，再按其当前参数运行。没有工具就标NOT RUN，继续源码分析；不复制作者机器路径、不默默下载工具，也不把查询适配器当已有执行器。

相关修改完成后运行所需检查；只有新变更、失败或未解决疑问才扩大或重复。保存参数向量、工作目录、退出码、stdout/stderr与输入身份；解析失败保留原报告，并标INCONCLUSIVE。

静态、部署、加载、渲染和场景结果独立记录。无报错、给出复现步骤或工具已安装，都不等于玩法通过。

研究参考：[ReikiMaple 的 Tiger 调试技能](https://github.com/ReikiMaple/Skills-for-CrusaderKing3-Modding/blob/d3098dd0551adc39f067eb3ed4fb6a15a7003644/ck3moddebug/SKILL.md)。此处提供本项目诊断方法，不附上游技能或Tiger程序。
