# 文件、参数与重复求值检查

## 文件与定义

修改前确认实际数据库和目标owner；保留BOM、换行、稳定键名及未改内容。新建文件参考当前schema和同类加载路径，不凭文件夹名字推断子目录语义。重命名前检索定义的读取者和调用者。

## 参数与值的寿命

把调用点的参数代入被调用定义，检查替换位置、scope及期待类型，特别是trigger/effect/value表达式不能互换。参数替换只改变展开文本，不会自动冻结动作发生时的数值。

需要历史结果时确认求值时刻和保存owner，再决定是否存快照；正确的动态读取不必为了复用而新增持久状态。

## 频繁求值

先确认执行频率、遍历集合与已观察成本，再优化查询。缩小查询应仍覆盖用户要求的目标，不能靠新增玩法资格消除负担。提取成scripted_trigger或script_value表示复用，不自动形成缓存；缓存必须说明保存、刷新与失效条件。没有同条件对照不宣称性能提升。

对重复定义、on_action扩展和临时scope，按当前来源确认注册、输入类型、覆盖与重复执行；旧教程不能代替版本证据。
