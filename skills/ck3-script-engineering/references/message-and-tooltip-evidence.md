# 消息冻结、提示和本地化

先区分消息数据、渲染与实际效果的消费者。修文字不改变已验证的资产动作。

## 每条消息独立保存结果

历史摘要不可变时，记录动作前库存、动作后实际增量，再在本条消息上下文中保存实收/转移/剩余/数量，最后生成摘要。不要让旧消息继续读取后续会重用的角色变量。

`send_interface_message` 内保存scope value再交给 `custom_tooltip` 是历史项目采用过的组合；迁移前核对当前版本接口、scope与值的寿命，不当作跨版本无条件范例。

用两次不同结果检验冻结：首次实际转移500，第二次为0，旧消息仍应显示首次结果。只看最新消息不能区分。requested不等于实收。一次汇总、自动零额静默或手动零额反馈按用户产品要求决定。

只抑制通知时，条件只包通知语句；不能为消除刷屏关闭整个原生on_action，连带丢失发展、计数或其它效果。

## 提示与效果分别验证

- 金额易截断时，把实际支付放在短提示前部，继续读该次实付值。
- 悬浮文字说明来源、目标、具体对象及费用。隐藏不完整自动预览时，将去除显示包装后的执行序列与旧候选逐项对照，确保未删或重排效果。
- 决议分类用当前数据库存在的键；分类错误不应导致普通入口新增debug资格。
- 有生成器就同时修改生成器与产物，保持编码；重生成后hash不变才能证明幂等。
- 源码/静态通过只支持包装未改变事务，不能替代新悬浮框、分类、金额与本地化的实机显示验证。

## 精确键名跟调用方

先追调用、查当前语言实际定义，再补准确键。历史原版出现过 `HAS_BULDING_TRIGGER_THIRD` 这样的拼写；不要凭词义擅自改成 `BUILDING` 后补一个无人调用的新键。换版本要再查是否已经修复，避免重复覆盖。条件提示缺字不构成修改触发器行为的依据。
