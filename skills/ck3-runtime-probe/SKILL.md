# 最小运行探针

先做 [接口核验](../ck3-reference/SKILL.md)。只有源码仍不能区分的重要问题才做实验，不连续堆叠单候选猜测。

1. 固定疑问、版本/候选哈希、对象身份和PRE基线。列候选ID、输入、预期关系与可证伪判据，覆盖baseline/control和必要中间量；独立候选可以同批观察，破坏性或互扰候选隔离。
2. 先读实际值，再计算，再写入，再读后置值；区分请求量、预计量、实际差值与GUI显示。记录精确值及单位，不因取整抹掉差异。
3. 只加入判别所需日志/临时UI，标记探针owner、移除范围和恢复条件，不顺便改变正式玩法。没有被证明的逆操作就不承诺回滚；存档恢复也须核对关键对象和状态。
4. 用户执行时给精确场景、步骤、观察点、预期关系及需要返回的日志/截图；自动执行另按 [游戏验证](../ck3-hybrid-gameplay-testing/SKILL.md) 确认通道与授权。
5. 只有实际观察到的结果才能标 PASS。截图值不证明语义，ACK不证明执行。部分变更用PRE/POST与阶段中间点定位最早失败处。读取器须先对照原始序列化结构验证，不能把读取器误报当机制故障。
6. 保留失败路线、原因、适用版本及重新开启条件；新版本或真正新证据才重开。修源码后需新运行证据，静态修复不撤销旧失败记录。

结果用 [实验记录](templates/probe-result.md)。热加载只在当前版本与文件类型有证据时采用，核对同进程实际变化；不推广成所有脚本即时生效。普通模式和调试模式分别记录，必要时用 [普通模式检查](references/ordinary-mode-acceptance.md)。
