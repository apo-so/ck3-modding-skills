# 普通模式与真实样本验收

按本次风险选择样本，不要求每次修复跑所有分支，不新增玩法条件。

## 正式入口与研发入口分别验证

- 在原生PRE/POST均没有诊断flag的样本中，从正常互动或决议提交，核对正式动作不依赖测试开关。按钮可见或诊断按钮成功不能证明这一点。
- 另留真实旧诊断flag、关闭引擎debug，查看完整决议列表和管理窗口，验证研发入口不会因旧flag泄露。此分支只检查UI即可，不为看隐藏状态再变更资产。

## 资产身份和结构

保存精确目标对象，取消与确认分别比较头衔/住所、holder、位置、资源及建筑结构。只计顶层建筑数量会漏嵌套槽位。来源不明的住所不可当Mod额外对象删除，原生载体禁毁。

序列化残留记录、关联仍在、可用资源和UI能操作是不同判据。先验证读取器能正确解析原始PRE/POST，再判断动作；不将读取器预测值当原生内容。

## 延迟结果与恢复

只有用户要求的语义涉及延迟清理、资源灭失、重载或重新创建时，才构造相应样本。动作当时的POST不能证明后续不会复活；重载或重建实际观察分别记录。无接收方资源必须灭失不是通用规则，也不为凑样本拆原生载体。

## 复用范围

仅词条修改可复用未变事务证据，但新文字需新显示验证。相同安装hash不证明正式目录重新冷加载。单次崩溃不能定位责任Mod，后续成功也不抹掉失败或证明长期稳定。

没有合格目标、未提交或点击禁用入口，分别记录BLOCKED_NO_SAMPLE、NOT RUN或UI状态，不能直接判引擎效果失败。保留失败与后续修订结论，不用最终通过覆盖原始观察。
