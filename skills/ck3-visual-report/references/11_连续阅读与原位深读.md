# 连续阅读与原位深读

## 反馈来源与适用范围
本模块默认采用单线阅读，避免切换模式时重复阅读共同正文。此偏好仅针对机制学习报告。

## 设计目标
读者沿一条主线读完核心问题。进一步学习时只获取当前位置的增量信息，不返回页首、不重看共同正文，也不丢失已经展开的内容。

## 默认组织
- 按读者问题组织少量主题章节，不把内部研究台账的16个维度原样当成16个必读章节。
- 一个事实在主线上解释一次。结果、条件和关键限制保持可见；完整调用、推导、源码和资料编号在相关位置展开。
- “为什么”“具体怎么做”“看真实代码”可以是局部折叠，不要同时再写一套重复的重点版和完整版。
- 深读标题应告诉读者会增加什么，例如“看创建参数与作用域”，不要只有“更多”。
- 长细节提供“收起，继续阅读”；来源链接提供明确返回原句的动作。保存语义锚点及其屏幕偏移，比仅记滚动像素稳健。
- 打开检索面板时先保存阅读锚点，再转移焦点；不要等焦点移动已经引起滚动，才记录所谓的原位置。
- 搜索帮助定位主题和细节；清空搜索后保留原正文和阅读位置，不用搜索结果替换整条主线。
- 原样/教学源码是同一对象的局部对照，可原位切换或并列折叠，不应让用户重走正文。

## 什么时候可以有全局模式
当两种视图确实服务不同任务，例如面向读者的叙述与逐项审校台账，可保留；先证明区别是信息组织/任务，而不只是隐藏少量章节。切换必须保持同一内容锚点、局部展开状态和返回路径。

## 检查真实阅读动作
1. 默认正文是否足以回答问题，有没有必须来回翻找的定义。
2. 读到中段，展开当前说明：触发点基本不移、其他说明不变，后续正文顺延。
3. 从一段话进入源码/来源后返回：回到刚才那句话附近，不能回页首。
4. 收起长细节：读者能继续当前主题，不因页面高度变化跳到无关段落。
5. 320/390宽度重复上述动作；工具栏不应占掉大半屏。
6. 无脚本仍能阅读主线与原生折叠；打印后恢复阅读与展开状态。

测量默认可见正文量可以帮助比较，但少字数不等于好阅读。不能为了缩短删掉重要条件、主要后续或诚实的未验收说明。
