# 结构化底稿字段说明

生成器接受一个 JSON（结构化数据）对象。七份报告底稿模板与四份示范都采用下面的合同；研究复核清单是另外的文件。渲染只转换字段，不进行游戏推理；填写质量决定报告事实质量。

## 顶层字段

| 字段 | 内容 |
|---|---|
| meta（报告元数据） | 标题、身份、版本、范围与验证状态 |
| sources（来源列表） | 所有章节、卡片、源码使用的证据条目 |
| sections（章节列表） | 依照固定顺序的十六章，不可删章 |
| cards（案例列表） | 零张或多张完整字段卡；没有时说明范围 |
| code（代码摘录列表） | 原始文本和教学文本，可为空 |

## 报告元数据

`title`（中文标题）、`subtitle`（副标题）、`game_version`（本轮样本游戏版本）、`scope`（研究范围）、`report_version`（页面版本）、`basis`（证据基础）、`verification`（验证状态）都是非空文本。

`profile`（报告分型）的合法值为 `event`（事件）、`scheme`（计谋）、`interaction`（互动／决议）、`state`（变量／状态）、`value`（数值／资源）、`design`（设计比较）、`behavior`（人物行为）。

`status`（页面身份）使用 `template`（空白模板）、`demo`（模板演示）、`report`（正式报告）。正式报告不允许残留“【待填写】”和双花括号占位；“待确认”是合法研究边界，不应被强行替换成确定结论。正式报告身份不是研究完成标记；资料不足的边界报告仍可交付，应在首屏和覆盖清单公开未完成项。

## 来源条目

每项必须有 `id`（稳定编号）、`name`（中文名称）、`kind`（来源类型）、`locator`（文件版本、路径、符号与行段定位）、`boundary`（能证明到哪里）。

来源类型只能是 `game_source`（游戏源码）、`localization`（本地化）、`report`（旧研究报告）、`design`（设计材料）、`method`（方法标准）。不要谎填类型以通过验证。

编号使用英文字母开头，仅含字母、数字、连字符或下划线；不要把完整路径当编号。页面会把它标为“来源编号”，标题另写中文。

## 章节条目

每项至少有 `id`（固定章节编号）、`summary`（中文摘要）、`evidence`（证据标签）、`source_ids`（来源编号列表），可加 `blocks`（内容块列表）。

固定顺序在生成器 `SECTION_IDS`（章节序列常量）中定义。最稳妥的方法是复制七份报告底稿之一，不重新手写顺序。证据标签详见《来源与研究边界》。涉及游戏事实的章节不能无来源；“本轮整理”只能用于方法、结构和范围说明。

支持的内容块：

| 类型 | 字段 | 用途 |
|---|---|---|
| paragraph（段落） | text（文本） | 解释普通结论 |
| callout（提示） | title（标题）、text（文本） | 关键边界或错误提醒 |
| cards（卡片组） | items（条目，每项标题和文本） | 选择结果或条件对照 |
| table（表格） | headers（列名）、rows（逐行数据） | 对照矩阵；每行列数相等 |
| transitions（转移边） | items（每项 from／to／cause，即来源、目标、理由） | 互斥、延迟、循环与因果 |
| formula（公式） | text（公式文本）、boundary（假设与口径） | 静态公式与边界 |
| calculator（计算器） | kind=allocation（单持有者份额分配教学模型） | 仅用在明确允许其简化假设的设计／资源页 |

文本会转义，不支持直接注入任意网页代码。需要新增组件时先扩展生成器和测试，而不是在输入中塞脚本标签。

## 案例卡字段

必须填写 `id`（本报告编号）、`title`（标题）、`layer`（层级）、`category`（类别）、`result_type`（结果类型）、`root`（根来源）、`eligibility`（资格）、`viewer`（谁看到）、`actors`（作用域人物）、`original_text`（原文或缺失声明）、`options`（全部选项或范围声明）、`direct_effects`（直接结果）、`hidden_effects`（隐藏共同结果）、`system_effects`（系统影响）、`follow_up`（后续）、`completion`（完成度）、`end`（真正结束）。

另外填写 `evidence`（证据标签）、`source_ids`（来源）、`recommended`（是否推荐，必须是真／假布尔值）、`weight`（相对权重，非负有限数或空值）、`code_ids`（所引用的代码摘录编号，可为空列表）。

未知权重使用空值，不能假填零。排序权重不等于计算概率。示例卡是阅读节点时标题必须明确，不可冒用实际事件编号。

## 双源码条目

必须有 `id`（编号）、`title`（中文标题）、`origin`（摘录身份）、`source_id`（来源）、`raw`（原始展示文本）、`teaching`（教学文本）、`boundary`（保真范围）。

摘录身份为 `game_source`（游戏原文件）、`localization`（本地化原文件）、`report_excerpt`（历史报告所载摘录）或 `concept`（概念伪代码）。前三者的来源种类分别对应 `game_source`（游戏源码）、`localization`（本地化）、`report`（旧研究报告）；历史页所载本地化仍属历史摘录，不能升级为本轮本地化原文件。

历史摘录可包含代码、故事或选项原文，统一显示“历史报告原文摘录”。1.1旧底稿若为绕过缺少类型而把实际本地化写成历史摘录，新版会拒绝来源种类错配；只有重新核对实际本地化原件、记录迁移后，才在新底稿副本改为`localization`（本地化），不能仅按文本外观或为通过检查而改标签。旧底稿与旧成绩保持不变。

教学文本包含 `# 中文：` 注释并保留原行，实质深度由复核检查；原始文本不能混入本轮新增解释。历史原文已有的中文注释必须保留，不因含有教学语句而从原始视图删除。

展示文本统一使用换行符 LF（换行），原文件字节另存。渲染器计算展示摘录哈希；它不会验证摘录是否真的来自声明的游戏文件。

## 独立研究复核文件

复制 `templates/研究复核清单.json`，在动笔前登记覆盖要求，交付前补齐定位和实际复核结果。它不属于页面底稿的顶层字段，由 `scripts/verify_research.py`（研究记录与来源校验脚本）读取。冻结底稿后填写其字节哈希；源码提取范围、来源根目录与七个语义复核维度的接口见 `10_研究复核与来源校验.md`。

## 默认工具限制

一个新报告包含一个汇总浏览器；支持的组件与计算器类型有限。不强行把复杂故事、任意图表或多资源算法压成单持有者模型。扩展前先更新结构合同、浏览器退化和验收测试。输入文件是受控研究数据，不是运行任意代码的接口。

## 人物行为分型

`meta.profile`（报告类型）支持 `behavior`（人物行为），对应第七份底稿。它仍使用同一套16章、案例卡、来源与双源码契约，不引入新的“通用人格算法”。 `layer`（机制层）可用资格、权重、贡献、执行等中文值；`weight`（相对权重）在不是单个候选权重时填写 `null`（未知或不适用），不能为了排序填零。新卡必须说明谁在决策、读谁的数据以及影响哪一层。
