# 统一研究与呈现规范

## 动笔前：按问题建立覆盖清单

先把用户要求拆成可核对项，记录必需事实、完整故事与选项、数值、必要源码、后继及证据边界，逐项映射到计划交付的位置。复刻旧报告时，依据实际旧页盘点，不把模板中的少量示范卡当作原报告范围。内容未知也登记缺什么；不为填满清单虚构结论。清单与复核方法见 `10_研究复核与来源校验.md`。

## 一、16 个研究维度，展示章节按阅读任务组织

| 序号 | 章节 | 必须回答 |
|---|---|---|
| 00 | 研究身份证 | 研究什么、哪一版文件、范围、根系统、证据与验证状态 |
| 01 | 15 秒看懂 | 为什么发生、最重要的结果或能力边界是什么 |
| 02 | 选择、收益与代价 | 玩家／系统有哪些分支，每条差异是什么，共同部分是什么 |
| 03 | 主要后续与真正结束 | 哪些状态延续、下一步怎样触发、何时彻底结束 |
| 04 | 完整生命周期 | 启动、运行、推进、执行、循环、失效与清理分别在哪 |
| 05 | 入口与条件 | 根入口、可见、允许、候选、接受或抽选分开 |
| 06 | 人物和作用域 | 当前是谁、保存了谁、后继根人物是否变化 |
| 07 | 数值与随机 | 单位、公式、基数、倍率、上下限、取整、随机层级 |
| 08 | 事件／机制浏览器 | 完整研究范围、分类、检索、唯一量与引用量 |
| 09 | 最终结果矩阵 | 成败、暴露、拦截、接受、拒绝等实际存在的维度 |
| 10 | 长期状态 | 持有者、建立、读取、变更、清理、继承与存读档边界 |
| 11 | 完成度与不确定项 | 哪些已定位、仅索引、已详解、未追完、运行待验 |
| 12 | 教学注释源码 | 原结构加中文逐句解释，保持上下文指代 |
| 13 | 原始证据摘录 | 原样保真，标明来自游戏文件还是历史报告摘录 |
| 14 | 来源索引 | 版本、路径、符号、行段、原文件哈希与引用关系 |
| 15 | 修改与验收 | 本轮做了什么、删了什么、检查执行情况与未解问题 |

“15 秒”是首屏可理解性目标，不是对读者实际阅读时间的保证。空白母版保留占位；正式页必须填实质内容。无对应机制时写“不适用＋理由”；没有证据时写“待确认＋缺什么”。不能用“没有”同时指代二者。16个维度齐全只说明覆盖骨架齐全；页面身份为正式报告不等于研究完成。资料不足时可交付诚实的边界报告，首屏明确未完成项，不能称为完整复刻。

## 二、单线阅读，原位深读

先提供一条能从头读到尾的主线。机制和证据是相应问题旁的增量细节，不是另一遍相同正文。研究底稿可保留16个维度，页面导航可以合并成更少的主题；合并后仍需有内容覆盖映射。

默认采用段落旁的原生折叠、局部代码对照与可返回的来源链接。每次展开只改变当前内容，保留其他展开状态和读者当前位置。关键条件、主要后续、风险及未验证边界不能只藏在折叠中。

不要用“重点模式只藏几章、完整模式再显示全部”的方式制造两条几乎相同的阅读路线。确需不同任务视图时，先说明各自的信息增量，并验证切换仍停留在同一语义锚点。详见 `11_连续阅读与原位深读.md`。

首屏直接回答问题；来源编号、文件路径和审计记录供需要时核对，不占据第一阅读层的大部分空间。

## 三、根入口与流程

每个根入口记录类型、具体系统、谁主动、触发时点、候选方式、满足条件是否立刻发生、当前节点和后续。直接父事件和根来源分开。事件调用事件不自动决定整条机制的根类型。

每条转移必须有来源、目标、原因和必要时的时间。可用原因包括主动点击、周期检查、资格通过、随机抽中、阶段完成、延迟到期、对象失效、继续循环。不同分支分开，不画成所有节点依次必达。

遇到未取得定义的调用、常量或默认作用域规则，逐项登记调用位置、缺失定义和受影响的结论。只见本对象未直接读取某属性，可以据此限定本对象的显式读取；不能进而断言缺失的辅助函数、后继或最终结果也不受该属性影响。

## 四、源码、本地化与中文

原版标题、正文、选项、动态占位符来自实际本地化文件，标明语言和键；缺失则写缺失，不能补译后标为原版。研究解释另段呈现。代码、文本和脚本数值互相指向；符号名本身不等于功能证明。

旧页中的完整故事、原有中英文注释、省略标记和动态占位符同样属于历史证据，不能删除后声称原样。故事概要不代替原文，指向摘录的链接必须落到真实存在的内容。保真边界详见 `05_中文注释与双源码.md`。

英文技术词每次出现立即中文括注，包括标题、图示、表格、工具提示和按钮。原样保真区不修改机器标识，旁边给用途和中文说明；不要用保真区豁免解释正文。文件路径是定位资料，前置“源文件路径”并给功能说明，不把路径当正文结论。

## 五、数值和概率

先给资源与实际变化，再展开公式。公式必须写输入是谁、单位、基数、倍率、上下限、取整、读取和执行时点。公式不全时不生成确定结果。教学假设要紧邻输出，不只写在页尾。

逐项核对增减方向、点数与百分比、作用对象、条件系数及其生效范围；共同结果与独立条件分项不能随意合并。相同字段名须按所属对象解释：候选集合的数量上限、评分分项的截断和总值边界不是同一规则。没有默认读取者的接口证据时，将人物归属标为推断并说明依据，不能借相邻字段的作用域注释升级为直接确认。

随机区分根时钟、发生门槛、无事件层、候选资格、相对权重、事件内部随机、最终成功、暴露与保护拦截。条件概率可以在冻结候选集合和参数的情况下演示；不能未经独立性证明将多个概率相乘。无事发生是有意义的结果，不能从分母消失。

## 六、事件卡与完成度

每卡有编号／标题、根来源、出现资格、看到的人、人物指代、原版文本及分支、所有选项、直接结果、隐藏共同结果、系统影响、后继和结束、双源码、来源、完成度。隐藏中转没有独立正文时明确说明。

超过十个事件使用检索浏览器。支持按编号、标题、人物、结果、后续搜索；按层级、类别、结果筛选；按研究顺序／权重／标题排序；推荐、展开当前、收起全部。权重未知不写零，跨不同池的权重不可当可比较概率。

完整事件清单、完整文本提取、人工逐项详解、根入口追踪、游戏运行验证使用不同计数器。不知道分母则不算百分比。

交付前以同一条重要事实对照首屏、结果卡、正文、教学源码、底稿与来源台账；数值、方向、读取者或证据等级修正后，同步所有出现位置，再重新生成页面。详解完成度取决于实质解释覆盖，不能用原始行数或中文注释数量替代。

## 七、原版与模组边界

原版研究不混模组新机制。设计比较可引用原版作为参考，但每个方案分别标“原版已有”“模组已实现”“设计待实现”“引擎接口待验”。历史故事原型如被用户要求，须区分史料、注引、小说、模组新编，默认不强加给纯机制页。

## 八、单文件交付

新报告内嵌样式、脚本、文字和案例；不联网取数据、不加载远程字体。原始游戏文件可另存证据包，但报告中用于核心结论的摘录仍可独立读。使用系统字体；不分发字体文件。

手机重点内容纵向排列；大表可转成带列名卡片。颜色不能是唯一状态；按钮、筛选与完成度都用文字。无脚本必须能读正文和打开原生折叠；打印要显示完整内容并在返回后恢复筛选和展开状态。
