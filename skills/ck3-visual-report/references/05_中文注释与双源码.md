# 中文、原文与双源码

## 正文不让读者背术语

错误：先在开头解释 Scope，后面全部只写 scope:target。

正确：每次写 Scope（作用域）和 scope:target（当前事件保存的目标人物），并在上下文变化后重新说明目标具体是谁。优先直接用中文叙述，不为展示专业性人为增加英文。

正文中的脚本标识符每次紧跟功能解释，例如 sway_end_effect（拉拢轮次收尾效果：按累计状态决定重置或结束）。仅写“收尾效果”但不解释此处作用，信息仍可能不足。

## 保真例外必须有边界

原始游戏代码、原版本地化、文件路径、机器可读数据的键不能为了中文化而改写。这些放在明确标注的证据区，配紧邻中文说明。正文不能大量放入“原始区”绕开解释责任。

动态本地化如 [target.GetTitledFirstName]（运行时替换为目标的称号与名字）保持在原文；解释可以逐项注释，不能把随机的人名填入后仍说是原版文本。

## 教学代码怎么加注释

保留原语句顺序、缩进语义和花括号结构；在有关语句下添加 `# 中文：` 注释。说明这一步是条件、过滤、效果、提示还是随机倾向，并明确当前人物。

先划定本次详解的完整对象或片段边界，再逐条覆盖有实质语义的语句。说明当前读取谁、判断或改变什么、数字的方向与单位、嵌套条件怎样限制执行；同名键按所在对象重新解释。相邻的纯括号或重复结构可以合并说明，但不能把一整块复杂逻辑都归为“这是原始语句”。历史已有注释可沿用，仍须检查其是否足以解释本次研究问题；新增注释数量和密度都不是教学通过条件。

```text
if = {
    # 中文：开始条件分支；不是一个独立的周期入口。
    limit = {
        # 中文：只有下面条件成立时，才执行这一分支的效果。
        exists = global_var:ai_voluntary_laamp_count
        # 中文：检查固定名称的全局计数变量是否存在。
    }
}
```

上面只演示注释格式，省略了执行体，不能标为可安装完整代码或游戏原始片段。正式解释要继续写出存在时、不存在时和调用上下文。

## 原始摘录怎么保真

摘录声明来自“本轮游戏原文件”“本轮本地化原文件”“历史研究页所载摘录”或“概念伪代码”，与来源种类一致。历史页内已有中文教学注释仍是该历史摘录的原文，不能为了得到纯脚本而删除。旧页的故事全文、格式标记、动态占位符和原有省略号也保留；来源本身不完整时明确不完整。

从真实文件或历史网页实际提取并保留原件，登记字节哈希、文本范围及提取方式。网页代码块使用解析后的文本，说明实体解码；展示文本可声明统一换行，不能把删注释、合并行、重排或改写称为仅换行规范化。非连续摘录分段给出定位；确需整理版本时另作整理视图，保留可独立核对的原样摘录。长块截取说明省略范围，不能以局部片段声称完整对象。

教学版本新增注释后不再是原样；双视图标题必须让读者一眼区分。需要精确复制时提供原始视图或独立源文件，不让读者先手动删除教学解释。

展示摘录自身的哈希只证明页面内部文本一致。将摘录与独立保存的来源按已声明范围比对，才能验证来源匹配；来源标签和作者填写的路径不能替代这一步。具体复核合同见 `10_研究复核与来源校验.md`。

## 人工检查问题

看到一句英文是否要翻回前文？换事件后“当前角色”是否仍被错认？看到 `show_as_tooltip`（只显示效果提示）时是否误以为实际执行？看到 `ai_chance`（人工智能选项倾向）时是否误以为玩家被限制？同名字段的中文解释是否错误套用了另一个对象？这些问题须回到具体上下文核对，不能仅靠裸英文扫描器或注释计数判断。
