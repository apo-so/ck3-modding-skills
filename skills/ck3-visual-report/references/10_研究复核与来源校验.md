# 研究复核与来源校验

本流程用于正式研究、旧报告复刻与边界报告交付。它把可自动验证的文件与提取检查、实际完成的语义审阅、尚未完成的研究分开记录。生成成功或页面结构通过，都不能替代本流程。

## 先立覆盖范围，再写报告

复制 `templates/研究复核清单.json`，依据本次用户要求和实际材料登记覆盖项。每项描述可核对的内容要求；例如某对象的全部选项、完整故事、数值条件分项、必要源码、下游调用或长期状态。不要只登记章名或笼统写“完整研究”。分母来自本次材料，不能把模板示例数量或旧报告自报数量直接当作本轮完成数量。

写作时将要求映射到真实章节、卡片或源码编号，缺资料也保留该项并说明缺口。原文收录与实质解释是不同要求；需要完整原文时，故事概要、原文链接或几张代表卡不能替代。用户要求逐条解读时，以完整对象或明确片段为边界覆盖有实质语义的语句，不以中文注释数量判定。

## 来源必须能够独立复查

保留本次实际使用的来源文件及字节哈希；从该文件提取摘录，记录行段或网页元素位置。原文件中的中文注释、故事全文、动态占位符、格式标记和已有省略号都属于原文。来源缺失或原页仅有节选时，明示其证据上限。

展示摘录允许已声明的换行规范化；网页元素提取包含文本解码，应在保真边界说明。非连续片段登记各自范围与连接方式。删注释、重排或改写不能冒充换行规范化。需要整理解释时放在教学视图，仍保留可核对的原样视图。

文件存在、哈希一致、摘录匹配只能证明该来源与当前报告的对应关系，不能证明它是官方文件、版本声明真实或研究解释正确。历史报告与本轮源码、本地化原文件的来源身份分别核对。

## 七个语义复核维度

| 维度 | 核对什么 |
|---|---|
| 内容覆盖 | 要求是否映射到实际交付内容；完整故事、全部选项、必要源码和条件是否漏项；边界报告是否公开未完成项 |
| 事实、单位与条件 | 增减方向、点数／百分比、作用对象、时间单位、基数、各条件系数、局部截断和总值边界是否逐项正确 |
| 作用域与因果 | 谁决策、读谁、改谁；资格、评估、接受、执行与后继是否混淆；默认规则缺证据时是否标为推断 |
| 来源身份 | 本轮源码、本地化、历史转述、推断与设计是否准确区分，具体结论有无超出来源边界 |
| 原文保留 | 声称原样的内容是否来自声明范围；原有注释、完整故事、占位符及省略边界是否保留 |
| 教学深度 | 有实质语义的语句是否解释当前人物、条件与效果；同名字段是否按所属对象解释，是否用泛注释掩盖未解读 |
| 交付一致性 | 首屏、结果卡、正文、源码、底稿、来源台账和交接说明是否使用一致的数字、证据等级与完成度 |

对缺失的调用、常量和默认读取规则，逐项记录调用点、缺少什么、影响哪些结论。“本对象未见显式读取”不能扩大为缺失的辅助逻辑或未知结局“完全不受影响”。不同对象里的同名上限、门槛或权重也不能套用一条释义。

复核依据应指向具体原文、语句或差异；“已核对”“结构通过”“有中文注释”不是充分证据。实际执行者可做自查或独立审阅，记录真实身份与方法，不能把代理审阅写成人工盲评。重大事实更正后同步所有交付物并重新构建；最终记录绑定冻结后的底稿字节。

## 复核清单接口

清单是独立 JSON（结构化数据）文件，不加入报告底稿字段。字段如下：

| 字段 | 内容 |
|---|---|
| `schema_version`（清单接口版本） | 当前为整数 `1` |
| `draft_sha256`（底稿字节哈希） | 最终报告底稿文件的 SHA-256（文件校验摘要），不是解析后对象的哈希 |
| `sources`（来源文件） | 每项含 `source_id`（报告来源编号）、`path`（相对来源根目录的路径）、`sha256`（原文件字节哈希）、`encoding`（文本编码，例如 `utf-8-sig`） |
| `excerpts`（摘录提取） | 每项含 `code_id`（报告源码编号）、`source_id`（来源编号）和 `selector`（提取范围） |
| `coverage`（要求覆盖） | 每项含 `id`（要求编号）、`requirement`（实质要求）、`status`（结果）、`targets`（交付位置）、`evidence`（核对依据）、`reason`（缺口或不适用原因） |
| `semantic_review`（语义复核记录） | 含 `reviewer`（实际复核者）、`method`（实际方法）和 `checks`（七维记录） |

来源路径以命令的来源根目录为准。用实际存在的文件，不能填推测路径或只复制报告内的来源声明。底稿中游戏源码、本地化、历史报告来源均应有实际文件记录；方法和设计来源不强求原文文件。概念伪代码不要求原文提取；其他源码摘录应有对应的真实来源与提取记录。文件未取得时保留缺口，不能为清除待复核状态伪填哈希。

提取范围支持以下三类；数字例子仅演示定位格式，不是业务答案：

```json
{"kind":"lines","ranges":[[1,5],[10,12]],"separator":"\n","trim":"none"}
```

上例按一基行号选择闭区间；多个范围须升序且不重叠。先将CRLF/CR统一为LF，再只按LF分行，保留其他Unicode字符；末尾LF对应可选择的末尾空行。完整文本可用 `{"kind":"whole_text","trim":"none"}`。网页摘录可用 `{"kind":"html_elements","tag":"pre","indices":[0,2],"separator":"\n","trim":"none"}`；元素索引从零开始，须升序且不重复，解码HTML实体并将显式br标签转为换行。它提取元素中的文本，不模拟浏览器样式或任意块布局。`separator`（片段连接文本）只允许空串、一个或两个换行。`trim`（边缘空行处理）只能选 `none`（不删除）或 `outer_blank_lines`（去掉最外侧空行），不代表可以删除内部注释、空行或改缩进。

将所选范围保存为一个选择器 JSON（结构化数据）文件，使用确定性提取助手生成原始文本与配套记录，减少手工抄录和重排：

```bash
python -X utf8 -B scripts/extract_source.py inputs/源码.txt --source-root inputs --source-id S1 --code-id C1 --selector output/提取范围.json --output output/摘录结果.json --encoding utf-8-sig
```

输出中的 `source`（来源文件记录）和 `excerpt`（提取记录）分别填入复核清单的来源与摘录列表，`raw`（原始展示文本）填入报告底稿对应源码项，再另写教学文本。助手不会补全缺失源码或自动判断机制；提取结果仍要检查是否选中了本次需要的完整范围。提取与复核工具均拒绝把结果写回输入文件，包括指向同一文件的路径别名。

覆盖项的 `targets`（交付位置）使用 `section:章节编号`、`card:卡片编号`、`code:源码编号`；所指对象必须实际存在。外部来源台账或交接文件的具体对照可写入核对依据。

七维记录每项含 `dimension`（维度）、`status`（结果）、`evidence`（证据）、`reason`（缺口或不适用原因）。维度依次使用：`coverage`（内容覆盖）、`facts_units_conditions`（事实单位条件）、`scope_causality`（作用域因果）、`source_identity`（来源身份）、`raw_preservation`（原文保留）、`teaching_depth`（教学深度）、`cross_artifact_consistency`（交付一致性）。

逐项结果使用 `PASS`（经实际核对满足）、`PARTIAL`（部分完成仍有缺口）、`FAIL`（有明确错误或反证）、`NOT_RUN`（未复核）、`NA`（不适用，必须给理由）。未执行的项目不能填通过；材料缺失不是不适用。模板中的占位和未执行状态不能直接作为最终完成记录。

## 运行与解读结果

```bash
python -X utf8 -B scripts/verify_research.py output/研究底稿.json --review output/研究复核清单.json --source-root inputs --json output/研究复核结果.json
```

脚本验证来源文件、哈希、摘录提取、交付位置与复核记录完整性。它不自动判断游戏语义，输出状态也不是语义通过徽章：

- `CHECKS_COMPLETE_REVIEW_RECORDED`（检查完成且已记录复核）：确定性检查满足，所需复核记录已提交；语义可信度仍取决于记录对应的实际复核。
- `REVIEW_REQUIRED`（仍需复核）：缺来源、覆盖不足或复核未完成等缺口须公开，不能称完整研究已完成。
- `FAIL`（检查失败）：检查发现错误，先根据具体结果修正，再验证。

诚实的缺资料边界报告仍可生成和交付。保留它的未完成状态与下一步所需材料，不伪造来源、不把未知写成不存在，也不为了清除缺口而删除原要求。页面结构、浏览器功能、研究语义与游戏运行继续各自报告。
